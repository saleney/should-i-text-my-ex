# Should I Text My Ex? Project Instructions

This project is a tiny interactive decision toy whose charm comes from simplicity, escalating reluctance, and a clickable coin.

## Creative direction

- Preserve the playful, self-aware tone.
- Keep the coin interaction central.
- The experience should feel immediate and funny, not like a serious relationship-advice product.
- Do not add unnecessary explanation or generic app chrome.

## Behavior

- Preserve the intended escalating logic rather than turning the result into a truly neutral random coin toss if the current design intentionally discourages texting the ex.
- Repeated interactions should remain varied enough to feel alive.
- Keep copy and percentages/odds internally consistent when editing behavior.

## UX and mobile

- Mobile is a first-class experience.
- Keep the coin comfortably tappable and the result easy to read without awkward scrolling.
- Prevent overflow, clipping, and layout jumps.
- Test repeated taps and state changes on small, standard, and large phone widths plus desktop.

## Code and important files

- `index.html` is the primary Should I Text My Ex? site and currently contains its markup, styling, and interaction logic.
- `am-i-the-red-flag/index.html` is an older/secondary Red Flag copy inside this repository. The public Red Flag project linked from `saleney.github.io` currently lives at `saleney/saleney.github.io/am-i-the-red-flag/index.html`. Do not assume this nested copy is canonical when asked to change the public Red Flag site.

## Scope

- Inspect before changing.
- Prefer the smallest clean implementation.
- Do not refactor the whole single-file project merely for architectural neatness unless explicitly requested.
- Preserve unrelated behavior and styling.
- Keep agent work concise and token-efficient.
